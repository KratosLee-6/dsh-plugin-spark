## Standards

1. **P2 — Multiline display names can inject contract headings.** `src/core.ts` placed a validated name directly after `#`; export then preview could turn `Original\n## Inputs\n- unexpected` into an extra input. This conflicts with inert, reviewed import and behavior/persistence expectations in CONTRIBUTING. **Fixed:** quoted `display-name` metadata, a single-line rendered heading, and a textarea editor preserve the exact name without structural injection.

   **多行名称注入契约标题。** 名称换行曾被当作导入结构，添加非预期输入。现用转义元数据与单行显示标题保存，编辑器也保留多行。

2. **P2 — Individually valid parents can produce an invalid grown contract.** Sixteen steps from each parent plus the handoff make 33 items; a 500-character step grows past its limit after the prefix. The normal advertised workflow offered growth without explaining the boundary. **Fixed:** preview and stored history expose an assessment; Studio disables growth with an actionable explanation and core returns `GROWTH_LIMIT`. No content is truncated.

   **合法父级组合后可能超限。** 现提前披露容量并给出拆分或缩短父级建议，历史记录同样适用，不静默丢弃内容。

3. **P2 — Fenced multiline steps lose code on export/import.** A fenced continuation was treated as an unrelated unmapped block. This undermines explicit round-trip preservation. **Fixed:** fences belonging to a mapped list item retain their literal text and cannot inject headings. Standalone blocks remain visibly unmapped.

   **多行步骤代码围栏往返丢失。** 现追踪围栏归属，将代码作为条目原文保存；独立代码块仍明确展示为未映射。

All three original Standards findings are resolved by the committed changes and regression tests. / 三项原始规范发现均有修复与回归验证。

## Spec

1. **P2 — Export/import round-trip is not faithful for multiline names.** ROADMAP requires “round-trip fixtures”; the injected-input example silently changes the contract. **Fixed** by the exact display-name path and editor regression above.

   **多行名称不满足契约往返要求。** 现完整保留名称与原始契约，包含界面保存验证。

2. **P2 — Accepted source sizes are inconsistently rejected by HTTP.** IMPORT promises a 64,000-byte UTF-8 source limit, but the old 70,000-byte encoded request cap rejects otherwise allowed text after JSON escaping. **Fixed:** bounded encoded overhead of `6 * 64000 + 4096` bytes; decoded Markdown and JSON source limits remain 64,000 bytes. A boundary test uses 64,000 quote characters and rejects a source one byte larger.

   **原文限制与传输层限制不一致。** JSON 转义后可超出旧请求上限。现给转义预留有界空间，同时保留解码原文限制。

3. **P2 — Growth workflow fails for valid input contracts at capacity.** ARCHITECTURE declares growth retains inputs, constraints and parent steps, while combined values may exceed the same contract limits. **Fixed:** preserve the full collision, expose a failed growth assessment and require smaller parents. This deliberately does not promise unlimited generations.

   **生长流程的容量边界未披露。** 现保留完整碰撞并明确拒绝超限生长，用户可修改父级重试，不承诺无限生长。

No material scope creep was reported. All three original Spec findings are resolved. / 未报告实质范围蔓延；三项原始需求发现均已整改。

## Supplemental boundary review / 补充边界审查

- **Competing insert:** the old SELECT-before-INSERT path could report the requested value as idempotent success even when another value won the insertion. `SparkStore.put` now attempts insert first and compares the actual stored row. The deterministic regression uses a real SQLite BEFORE INSERT trigger to introduce a competing row. It proves this interleaving, not general multiprocess throughput.
- **竞争插入：** 改为先插入、后读取实际已存内容比较；真实 SQLite 触发器测试证明该交错下不会误报成功，不将其称为多进程压测。
- **Committed write followed by failed refresh:** Studio used to report a generic failure despite a completed save. Save, growth and import now preserve success feedback and separately explain refresh failure. A browser test verifies the record survives a subsequent reload.
- **提交成功后刷新失败：** 保存、生长、导入均保留已提交反馈，并单独提示刷新问题；浏览器回归验证重载后数据存在。

The two axes overlap on name injection and growth capacity. There are six distinct original issues including this supplemental review. / 两轴在名称注入与容量问题上有重叠，计入补充边界审查后共六个独立原始问题。

## Follow-up review / 修复复审

The fence fix went through further independent review. Additional regressions were found and fixed before publication: malformed indentation could expose fake headings; a fence on the first line of a bullet could absorb later constraints/tags/parents; an inline triple-backtick span could be mistaken for an opener. One shared opener parser and explicit list ownership now cover top-level, first-line and continuation cases, including backtick and tilde markers. These are follow-up cases of the original fence finding, not inflated new original-issue counts.

围栏修复经过独立复审，继续发现并修正异常缩进、条目首行围栏及行内反引号误判。统一开始标记解析与列表归属覆盖正文、首行、续行及两类围栏。这些记录归属于原围栏问题的复审，不扩大原始问题数量。
